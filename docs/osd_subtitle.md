# HDMI 滚动字幕与 OSD 面板

本功能基于 `main` 的多分辨率、伴音和切换特效稳定链路。字幕与面板只在 HDMI 输出端叠加；以太网写侧预览和 `D` 读回仍显示原始帧，可继续用于像素比对。参考 demo 的硬编码字幕、演示计数器和旧版切换链路没有直接复制。

## 屏幕行为

- HDMI 固定输出 1280×720。字幕为 8×16 ASCII 字形，从 **y=504** 开始，水平从右向左每帧移动 **2 像素**；160 字符占 1280 像素，从进入到完全离开约 1280 帧（60 Hz 时约 21.3 秒），然后重新进入。
- 文本范围为 0–160 个可打印 ASCII 字符（`0x20..0x7e`）。空字符串清除字幕。上电默认无字幕。每次成功上传后，新文本只在视频 VS 边界整体生效，同时滚动位置重新从右边开始。
- 字幕使用白色字形及半透明黑底，黑底由原像素每通道右移一位实现，不占乘法器。脉动条仍在屏幕底部，两者之间保留空间。
- 右上角面板显示 `BRI 4/8`、`CON 2/6`、`VOL 8/8` 格式的**实际控制档位**，不是演示自增数值。显示模式为关闭、调节亮度/对比度/音量后显示 3 秒、始终显示。默认是调节后 3 秒。面板也采用白字和半透明黑底。

## PC 控制与协议

网页的“HDMI 滚动字幕”输入框可通过当前选中的串口或以太网通道发送，`发送字幕`和`清除`共用 `/api/subtitle`。键盘快捷键在输入框聚焦时停用。三个面板模式同时列在网页控制按钮中，也可由串口直接发送普通成对命令：

| 命令 | 作用 |
|---|---|
| `3` | 面板关闭 |
| `4` | 调节后显示 3 秒（上电默认） |
| `5` | 面板始终显示 |

命令字节余量充足；这三个设置只占已有单字符命令中的三个值。完整字幕另用事务传输，避免为每个字符分配命令。**每个事务字节**仍经过现有 `[byte, ~byte]` 成对校验。事务内容：

```text
0x54 ('T'), length XOR 0x80, length 个 (ASCII OR 0x80),
0x80 OR checksum[7:4], 0x80 OR checksum[3:0]
checksum = 原始 length XOR 原始 ASCII[0] XOR ... XOR 原始 ASCII[length-1]
```

字幕内容中的 `N`、`P`、`0` 等会被上传状态机消费，不触发换图或特效命令。编码后的长度、文本和校验字节均避开普通控制命令值；即使以太网开头的 `T` 包丢失，后续孤立负载也不会触发换图或调音量。长度无效、校验失败或字节间超时 100 ms 时，现有可见字幕保持不变。上传完毕且校验通过，写入非活动字库的文本等到 VS 再切换。前一次 VS 切换尚未回执时，新上传会拒绝，避免覆盖正在显示的库。

串口一次写入全部字节对。板侧以太网前端每个 UDP 命令包只接受一对字节，因此 PC 端将事务拆成 `length+4` 个包、约 2 ms 一包；它们复用原来的 `type=0x0001, length=0x0002` 应用头。网页的“已发送”只表示 PC 已送出，成功与否以板卡 `ACK 字幕上传` 为准。轻载局域网一般能顺序收到；若 UDP 字节包丢失，事务会超时失败，应重发。

`T` 的 ACK 仍是 8 字节 `5A` 格式：`cmd=0x54`，`flags.bit7=1` 表示校验成功并已安排 VS 切换，`0` 表示失败。ACK 的亮度字节 `bits[7:6]` 和 `S` 状态包的 underrun 字节 `bits[5:4]` 表示面板模式；其余已用字段保持原语义。`T` 的成功 ACK 表示事务成立，实际可见时间为后续 VS 边界。

## RTL 数据流

`ctrl_core` 所在的 `sd_card_clk` 域接收 `cmd_arb` 输出。`subtitle_cmd` 解码、检查长度/XOR/超时，并禁止上传字节进入普通控制命令路径。`subtitle_store` 使用两个 160 字节文本 bank：SD 时钟写非活动 bank，视频时钟同步读活动 bank，提交 toggle 经 CDC 到 VS 切换，再将确认 toggle 返回 SD 域。`subtitle_scroll` 以 VS 计帧；`subtitle_text_renderer` 与 `osd_panel_levels` 各用一个同步 `font_rom` 取 8×16 字模。`osd_visibility` 将控制档位 Gray 码跨域并在 VS 锁存，避免一帧中途改数字。`osd_composite` 将字形/底色与原视频合成，并同步延迟 RGB、DE、VS 以对齐字形掩码。

`scripts/gen_font.py` 可重复生成 `board/user_source/hdl_source/SD/font.mem`，覆盖 95 个可打印 ASCII 字形；综合输入为该静态 `.mem` 文件。TD 工程 `.al` 与 `syn_1/phy_1` 源列表已列入全部新增 `.v`，综合前请确认 TD 仍使用当前工程而非旧缓存。`font_rom` 默认从 TD 工程目录相对路径读取 `.mem`；若 TD 报找不到字库，先核查工程工作目录与路径。

## 验证与上板观察

快速验证：

```sh
make -C boardtest osd-unit
make -C boardtest uart
python scripts/web_console/test_subtitle.py
```

`osd-unit` 覆盖上传原子性、跨时钟双 bank、满长滚动回绕、字形像素位置、真实档位、3 秒显示和像素/同步合成。`uart` 检查旧命令与新 `3/4/5` 命令遥测。PC 测试检查 API、长度/字符限制及以太网应用包封装。这些测试不替代 TD 资源/时序报告和 HDMI 实屏验收。

上板建议依次观察：发送 `HELLO FPGA`、包含 `N0P012345` 的文本（确认不切图）、160 字符长文本、清除文本；切换 `3/4/5`，调节亮度/对比度/音量，观察面板真实档位与 3 秒超时；播放 WAV 和切图，确认音频、图像、特效与旧版本一致；按 `D` 确认 PC 读回无 OSD 叠加。
