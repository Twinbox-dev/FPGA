# 16 频点自研 DFT 音频频谱上板版

本版针对比赛要求中的“PCM 样本经 FFT 或自研 DFT 计算频谱能量，再叠加到 HDMI”。它计算真实的频率系数，不把音量历史柱伪装为频谱。**2026-10-09 用户确认频谱功能已上板成功**；当前音源的有效精度限制及静态时序违例仍需明确保留。

## 信号来源与阶段限制

现有 `wav_reader` 只接受 **24 kHz、8-bit、单声道 PCM WAV**。播放时每个样本重复两次形成 48 kHz，并从 8-bit 扩展为 24-bit HDMI 样本；扩位没有增加原始音频精度。频谱模块从 `aud_tick` 的每两个 48 kHz 脉冲取一次音量调节后的 24-bit 数值，得到原始 24 kHz 节拍。左右播放声道目前相同，频谱只分析一份。

因此首版可以证明 DFT 频段算法和音乐联动，但**不能把当前 8-bit 来源称为原生 24-bit PCM 采集**。用户决定先验证现有 WAV，再升级音源。后续优先考虑让配对 WAV 支持真正的 24-bit PCM，沿用 DFT 的 24-bit 输入口；也可另接真实 24-bit I²S 音源。现有每路约 2.35 MB SDRAM 音频缓冲在 24 kHz/24-bit 单声道下约容纳 32.6 秒，需同时重新验证播放与切图。

## DFT 与资源结构

- 使用 512 个原始 24 kHz 样本为一窗，频率分辨率为 46.875 Hz；每 512 样本更新一次，约 46.9 次/秒。
- 选择 16 个由低至高的 DFT 系数，频点索引为 `1,2,3,4,6,8,11,15,21,29,40,56,78,108,150,210`，约 47 Hz 至 9.84 kHz。每个频段独立计算 `X[k] = Σ x[n](cos θ − j sin θ)`，再取缩放后的 `Re²+Im²` 为能量。这是所选频点的直接 DFT，而非全 512 点 FFT。[SciPy 官方 DFT 定义](https://docs.scipy.org/doc/scipy/reference/generated/scipy.fft.fft.html)
- 输入保留有符号 24 bit；余弦、正弦是可复现生成的 Q1.15 ROM，累加使用 50 bit。16 个频点分时复用一个 RTL 乘法器，不为每个柱子复制乘法器。乘法器最终映射成几块 DSP 必须以 TD 报告为准。
- 两组 512×24 样本窗口乒乓写读，同域运行；为匹配 BRAM 宽度显式拆成 1024×16 和 1024×8 两块。两块样本 RAM 在独立、无复位的 `spectrum_sample_buf` 中无条件同步读、条件同步写，避免首次综合将其错误展开为上万 FF。ROM 是 1024×16，前半存余弦、后半存正弦，分拍读取，并从与 RTL 同目录的 `.mem` 初始化。一次 16 频点计算需要约 3.3 万个核心时钟，远小于约 21.3 ms 的取窗时间。TD 已确认本版样本 RAM 映射到 BRAM；实际资源和时序见后表。
- 频段能量经过压缩映射和快升慢降后，仅把 16×8 bit 结果通过 toggle/确认信箱交给视频域；像素域在 VS 锁存整组电平，避免一帧中途逐柱变化。

## HDMI 外观与控制

频谱在底部 **y=582–715** 的局部半透明深色区域内绘制，16 根青蓝色能量柱位于 x=128–1151；高电平柱顶用少量琥珀色。字幕仍从 y=504 开始，二者不重叠。它不再用原先横贯全屏的蓝绿红渐变色块。`Q` 仍切换可视化，默认关闭；`'`、`;` 仍调四档灵敏度。绘制级只叠加到 HDMI，PC 写侧预览与 `D` 原始读回不含频谱。

`pulse_bar.v` 暂保留作旧效果参考，但顶层不再实例化。本版未修改音频送往 HDMI 的数值或时钟：分析器只旁路读取当前样本。

## 快速验证与后续验收

```sh
make -C boardtest spectrum-unit
python scripts/gen_spectrum_twiddle.py
```

定向仿真已验证：所选 `k=8` 纯音只点亮对应频段、`k=8+k=40` 双音分别点亮两个频段、静音使两柱回落；渲染器验证 VS 原子更新、字幕 y=504 空隙和 `Q` 关闭。系数生成脚本重跑后 `.mem` 的 SHA-256 不变。用户已确认频谱功能上板成功；逐图切换、长时间伴音与 PC 原始预览并未在本次单独记录为完整验收。

### 首次 TD 综合失败与修正

首次综合时，`spectrum_dft` 的两块样本存储出现 `SYN-5042 Failed to infer ... as BRAM`；门级报告中该模块膨胀到 **9,297 LUT、11,702 个寄存器**，全设计达到 **24,609/19,600 LUT、22,093/19,600 寄存器**，因此布局失败。这是样本 RAM 落入 FF/LUT 的映射问题，不是 16 频点乘加本身占用上万 LUT。该次日志还报告系数 ROM 的相对路径未找到。

修正版将 1024×16 和 1024×8 样本 RAM 移到独立、无复位、无条件同步读的 `spectrum_sample_buf.v`，模仿已成功映射 BRAM 的 `transition_line_buf.v`；ROM 参数改为与 `spectrum_dft.v` 同目录的文件名。修正版定向仿真再次通过。TD 日志已出现两个 `Infer Logic BRAM(u_spectrum_dft/u_sample_buf/...)`，系数 ROM 不再出现路径未找到警告。门级层级报告中的 DFT 模块从失败版 **9,297 LUT／11,702 寄存器**恢复为 **657 LUT／427 寄存器／3 BRAM／2 DSP**；其中样本缓冲子模块占 2 BRAM。层级 `lut` 列不是全芯片布线后 `#lut`，不能直接与下表相加。
