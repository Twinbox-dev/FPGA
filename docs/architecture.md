## 一、这个仓库是什么

**嵌赛'2026 安路选题一（TF 卡 BMP 图片 + 配对 WAV 音频 HDMI 显示）的仿真验证工作区。**

只放两样东西：厂商无关的可综合 RTL（`vsrc/`）+ Verilator 验证环境（`csrc/`、`tb/`）。
PLL/SDRAM/HDMI 等厂商 IP、引脚约束、上板集成在**另一个 TD 工程目录**，不在这里。

核心方法：**所有期望值由独立实现的 golden 模型现场算出**（`csrc/fat32_golden.cpp`
自己解析同一张卡镜像），RTL 与之逐字节/逐像素/逐样本比对。换一张卡、换一张图，
测试代码一行不用改。

## 二、数据怎么流

```
          img/card.img（FAT32 卡镜像，脚本生成）
                 │
        ┌────────┴────────┐  csrc/sd_card_model：引脚级 SD 卡模型
        │  SPI 四线（模式0）│  （上板时换成真卡，RTL 不动）
        ▼                 │
   ┌─────────┐            │
   │ sd_spi  │ ◄──────────┘   CMD0/8/55/41/17，390k→25MHz 双速
   └────┬────┘                超时重试 ×3，错误上抛
        │ 扇区字节流（512B/扇区，按 LBA）
        ▼
   ┌────────────┐   双 fat32_ro 主机共享一个 sd_spi：
   │ sd_arbiter │   音频(B)优先 + 迟到请求 pending 排队；
   └──┬──────┬──┘   写目标 FIFO 高水位停流（i_b_hold）
      │      │
  ┌───┴───┐  └──┐
  ▼       ▼     ▼
┌──────────┐  ┌──────────┐
│ fat32_ro │  │ fat32_ro │   图/音各一个实例：独立挂载、独立播放列表
│ （图 A） │  │ （音 B） │   目录项捕获 8 字节主名，供同名配对
└────┬─────┘  └────┬─────┘
     │ 文件字节流    │ 文件字节流
     ▼             ▼
┌─────────┐   ┌────────────┐
│ bmp_dec │   │ wav_reader │  BMP 认 'BM'，WAV 认 'RIFF'；
└────┬────┘   └─────┬──────┘  不是本类就报头错、不出数据
     │ 像素         │ PCM 样本
     ▼             ▼
┌─────────┐   ┌────────────┐
│ mem_sim │   │ audio_path │  双 FIFO 乒乓 + 48kHz 节拍：
└────┬────┘   └─────┬──────┘  装载期写 prim，续播期写 aud（边播边补）
     │              │         无配对提交双 FIFO 同清 → 静音
     │ read_req/ack │          ▼
     │ + read_en    │      48kHz L/R 样本（3b 板级再做 IEC60958 封装）
     ▼              │
┌──────────┐        │
│ vga_ctrl │ 640×480@60 时序 + 取像素
└────┬─────┘ （像素域，clk 的 1/4）
     ▼
 VGA 输出 ──► nvboard 看图 / TB 捕帧比对
```

顶层还有一块**轮播控制**（在 `top.v` 里）：挂载后自动显示第一张图，`btn_next`
上升沿切下一张（到尾回绕、跳过音频项），装载中按键排队到文件完成。切图时按
8 字节主名找同名 WAV 配对；**双就绪原子提交**——图片整帧落盘 + 配对音频就位
（FIFO ≥1024 水位 / 短文件流完 / 格式非法），等场同步沿同时切换图和音，
装载期间旧图旧音照常播放。坏图跳过不提交；配对 WAV 非法则静音不阻塞。

## 三、模块逐个说

### `sd_spi.v`（640 行）— SD 卡 SPI 主机

**吃**：扇区号 + 请求。**吐**：512 字节流 + done/err。

上电发 80 个时钟（CS 高）→ CMD0 进 SPI 模式 → CMD8 验电压 → CMD55/ACMD41
轮询等卡就绪 → 切 25MHz → 之后每次请求发 CMD17 读一个扇区。

**关键设计**：R1 等待 64 字节超时、数据令牌 2048 字节超时，各重试 3 次；
重试耗尽才上抛 `o_err`。**契约：err 路径保证此前没吐过数据**（数据只在 0xFE
令牌之后流动，而错误都发生在令牌之前）——上层因此可以放心重发而不必回滚。

### `sd_arbiter.v` — 双主机扇区读仲裁（3a 新增）

**吃**：A(图)/B(音) 两路 fat32_ro 的扇区读请求。**吐**：仲裁后的单路 sd_spi 请求 +
两路各自的数据/完成回报。音频优先；SERVE 期间监听非 owner 的迟到请求进 pending，
当前扇区服务完紧接着服务它（同拍切 owner 和 s_lba，无缝背靠背）。

**关键时序（文件头有完整约束，两个陷阱都踩过）**：
1. SERVE 无条件拉高 s_req——**退出到 IDLE 的同拍必须撤 s_req**，否则 IDLE 首拍
   的新请求会被 sd_spi 以过期 s_lba 接受（每扇区读到上一个 LBA）。
2. pending 切换路径**同拍要把 s_lba 换成 pend_lba**：sd_spi 回 READY 后 ~1 拍
   就采样 s_req，晚一拍更新又是陈旧 LBA（排队扇区读到的仍是上一路的 LBA）。
3. fat32_ro 在 i_ready=1 的下一拍才发 o_req——SERVE 中途到达的请求都是"迟到"
   请求，绝不能丢（丢了就挂载死锁），最多同时只有一路会迟到。

### `fat32_ro.v`（537 行）— FAT32 只读引擎

**吃**：播放列表索引 + 请求。**吐**：该文件的完整字节流。

四件事：**挂载**（LBA0 首字节 0xEB/0xE9 判 superfloppy，否则按 MBR 读第一分区项）
→ **BPB**（提 5 个字段算出 FAT 区和数据区位置）→ **目录扫描**（沿根目录簇链，
32 字节一项，跳过 LFN/卷标/子目录/已删除，按扩展名收 BMP/WAV 进播放列表）
→ **供数**（沿 FAT 簇链把文件字节吐出来，按目录项记录的 size 截止）。

**关键设计**：**纯流式解析，一块 512B 缓冲都没有**。所有多字节字段按"扇区内
第几个字节"捕获，目录项按"32 字节内第几个相位"解析（32 整除 512，项不跨扇区）。
小端字段一律**右移插入**（`{新字节, 旧值[31:8]}`）——左移会把先到的低字节推到高位。

3a 增量：目录项捕获 8 字节主名（`name_reg`）入播放列表，外加组合查找口
（`i_pl_idx` → `o_pl_name/o_pl_is_wav`）供顶层配对搜索；顶层例化两个独立实例。

### `bmp_dec.v`（155 行）— BMP 解码

**吃**：文件字节流。**吐**：像素流（无地址，归存储层线性生成）。

校验头（'BM'、640×480、24bit、不压缩）→ 数据区每 3 字节组一个像素
（BMP 存 BGR，要转 RGB）→ 按文件顺序吐像素（自底向上），**行序翻转归存储侧**
（`WRITE_V_FLIP`，见 mem_sim 一节）。`i_restart` 在切图时复位全部解析状态。

### `wav_reader.v`（254 行）— WAV 解析

**吃**：文件字节流。**吐**：PCM 样本流（L/R 各 16bit）。

**不能按固定偏移读**：WAV 是 RIFF 容器，`fmt` 和 `data` 之间允许插入任意块
（LIST/INFO、fact），ffmpeg 转出来的文件就自带 LIST 块。所以走 **chunk 链**：
读 `ckID(4B) + ckSize(4B)` → 认识就解析、不认识就按 ckSize 跳过。

格式限定 PCM/48kHz/16bit/1~2 声道，不合格报 `o_fmt_err`（不重采样——
兼容性靠入卡前的 `prep_media.sh` 转码解决，不搬 DSP 进控制路径）。

### `audio_fifo.v` / `audio_path.v` — 音频缓冲乒乓（3a 新增）

`audio_fifo`：2048 样本同步 FIFO（L/R 16bit），`i_flush` 秒清、`o_fill` 水位。
`audio_path`：两个 FIFO + 角色寄存器（aud_sel=播放中，prim_sel=装载中）。

**写目标三段式**（本模块最要命的一条）：
- 未提交过（`!i_play_en`）→ 写 prim（首图音频灌入）；
- 正在装载下一张配对音（`i_load_aud`）→ 写 prim；
- 续播期（已提交、无装载）→ **写 aud**——同一条卡流边播边补。若永远只写 prim，
  播放 FIFO 就只有装载期预存的 ~2k 样本（≈40ms），长尾 WAV 必然下溢。
- 无配对图提交（`i_silence`）：两 FIFO 同拍清空，否则 prim 里残留的上一张
  音频尾会被当成这张图的声音播出来。

**节流**：上游 sd_arbiter 按**写目标** FIFO 水位 ≥1920 停卡流（`i_b_hold`）。
卡速 ~3MB/s ≫ 48kHz×4B 消费，不停流会把 FIFO 写穿、尾部样本永久丢失。

### `mem_sim.v`（约 420 行）— 帧存储（SDRAM 替身）

**吃**：像素流（无地址）。**吐**：按显示顺序读出的像素。

**它不是一块 reg 阵列，而是例程 `frame_read_write` 的行为模型**：同名端口、
同样的 `req/ack` 握手、同样的 512 深 FIFO + 256 字突发、同样的写优先仲裁。
板级替换时上下游模块不用改。前身 `fb_sim`（给地址就立即写入）与板级接口有两处
本质不符，已删除：

1. **写口不接受地址**。板级地址由存储侧线性生成，生产者只能按顺序推数据。
   BMP 自底向上的行序由 `WRITE_V_FLIP` 参数在地址发生器里消化。
2. **写口没有背压**。例程连 FIFO 的 `full_flag` 都没接出来——写快了静默丢数据。
   所以这里不发明板上不存在的 ready，而是建模 FIFO 占用并在溢出时报警。

三个诊断输出把板上"静默发生"的事变成仿真可断言的事：

| 信号 | 板级现象 |
|---|---|
| `o_wr_ovf` | 写 FIFO 溢出 → 静默丢像素 |
| `o_rd_und` | 读 FIFO 下溢 → 画面横向拖影 |
| `o_len_err` | 传输长度非 256 倍数 → 状态机**死锁**（例程靠 307200 整除侥幸避开） |

系统仿真里这三个恒为 0（S7 断言），检测器本身会不会响由 `mem_sim` 模块测试的
T2/T3/T4 主动制造故障来验证。

**时钟比必须建模**：板级 mem_clk 100MHz、像素 25MHz。最初图省事让两者同频，
结果读 FIFO 水位被钉死在补水阈值 256 上、每帧必然下溢——行消隐这段唯一的空闲
带宽恰好被 `rfifo_cnt < 256` 条件挡在门外。现在顶层用 1/4 时钟使能把 `vga_ctrl`
放进像素域，比例与板级一致。

### `vga_ctrl.v`（88 行）— 视频时序

640×480@60（行 800：同步96/后沿48/有效640/前沿16；场 525：2/33/480/10）。
**场同步下降沿**发 `read_req`、保持到 ack（存储侧借此清 FIFO、从帧首重新取数），
随后 35 行场消隐用于预填；有效像素期逐拍 `read_en`，数据下一拍到，故 hs/vs/de
统一打 2 拍对齐（例程用 `video_delay` 打 21 拍做同一件事）。

跑在像素域：仿真由顶层给 `i_ce`（clk 的 1/4），板级直接挂 25MHz、`i_ce` 恒 1。
时序参数板级照用，输出形态要改（喂 AXIS 给 HDMI 核，而非直出 VGA）。

### `top.v` — 系统顶层

把上面接起来，外加轮播控制（配对搜索 → 开写通道 → 双就绪 → 场同步原子提交）
和 48kHz 音频节拍器（clk 分频，`audio_enable` 前不播）。仿真顶层是**单时钟**
（1/4 使能分出像素域，同 E5/8_vga 的做法）；板级是 100M(SD/SDRAM) + 25M(像素)
+ 125M(串化) 多域。

## 五、板级迁移（另一个 TD 工程）

| 模块 | 迁移动作 |
|---|---|
| `sd_spi` `fat32_ro` `sd_arbiter` | **原样搬**——只跟协议/仲裁打交道，仿真和板上是同一件事 |
| `bmp_dec` `wav_reader` `audio_fifo` `audio_path` | **原样搬**（背压问题已随 mem_sim 澄清：板级没有背压，改为约束生产者速率） |
| 轮播控制（top 内） | 整段搬 |
| `vga_ctrl` | 时序与握手照用，`i_ce` 接 1'b1，输出改喂 AXIS |
| `mem_sim` | **删除**，换例程的 `frame_read_write` + 加密 SDRAM IP（端口已对齐） |
| `top.v` | 重写（例化 PLL、接引脚、接 HDMI 核） |
| 新增 | PLL 配置、`.adc` 引脚、`.sdc` 时序、按键去抖、HDMI 核例化 |

**新增的部分官方例程全都给了**，是填空不是创作。已扫描确认**零个不可综合构造**
（无 `initial`/`#延迟`/`$display`）。

⚠ **迁移时必须配套的两条**（否则仿真全绿、板上出错）：
- `frame_read_write` 的 `WRITE_V_FLIP` 必须设 1 —— 行翻转归存储侧，`bmp_dec`
  按文件顺序供数。设成 0 会得到上下颠倒的画面。
- 生产者速率必须低于 `256/258 ≈ 0.99` 字/存储时钟。`bmp_dec` 是 3 个 SPI 字节出
  1 像素（约 0.01），余量极大；但**若日后给音频缓冲复用这套接口，要重新核算**。

例程情报（时钟实测值、App 接口形态、加密 IP 边界）见 `docs/design.md` 末尾。
