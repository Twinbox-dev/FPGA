# 双板媒体链路：实施边界

这是 `feature/dual-board-media` 的工作约定。单板稳定版固定在
`single-board-gt911-v1`；现有 `board_display/` 在迁移期间继续能独立播放，
直到板间链路和媒体装载均通过验证。`board_media/` 是另一块同型号开发板的
自包含 TD 工程。两板各自保留所需的以太网 RTL 和厂商 IP，不跨工程引用
Verilog 源文件；`boardtest/`、`docs/` 和脚本继续共用。

## 职责

| 媒体板（主控） | 显示板 |
| --- | --- |
| TF/SD、FAT32、BMP/WAV 解析、目录与配对、自动轮播决策 | 本地 SDRAM 帧/音频缓冲、转场、HDMI 视频与音频、OSD、频谱 |
| PC 的串口和以太网控制入口、媒体分包发送 | GT911 采集与光标、媒体收包/校验、转场完成回执 |

媒体板持有播放列表和当前装载会话。PC 控制命令先到媒体板；显示板的
触摸手势经板间链路上报媒体板。亮度、音量、效果模式等由媒体板转发到
显示板的本地寄存器。音频在切图时整段传到显示板缓冲，再由显示板按
HDMI 节拍播放；播放不依赖网络包实时到达。PC 可以控制和调试，但两板
自主运行时不要求 PC 转发媒体数据。

## 板间事务

一次切图按 `请求 → 图像与配对音频分包 → 完整性确认 → 显示板转场/换音频
→ 完成回执` 进行。显示板仅写入非活动缓冲；在所有所需媒体收齐并验证前，
继续显示和播放旧缓冲。数据包需要会话号、分片序号、总长度和帧级校验，
丢包或超时必须能重传或取消会话。图像/音频分片的候选编码见下文；实际
启用仍以板间 UDP 收发验证为前提。

初始网络规划：PC `192.168.137.1`、显示板 `.2`、媒体板 `.3`，两板使用
不同的单播 MAC。媒体板已通过 `.3`→PC 的以太网探针；待测改动将其静态
目的地址改为显示板 `.2:1`。正式协议仍需按包类型选择 PC/显示板目的地，
并锁存发送期间的地址/端口。第一轮先让两块板都使用已有 UDP 栈降低改造风险。
待真实资源报告出来，再评估显示板是否值得改成更轻的链路端点。

## 分阶段验收

1. 两块板各自的 TD 工程独立打开、综合；通过交换机互相识别并往返短包。
2. PC 命令到媒体板，媒体板命令到显示板；GT911 手势能反向到媒体板。
3. 先传固定图案并与显示板 SDRAM 读回逐字比较，再接 BMP/WAV。
4. 完整图像和配对音频反复切换后，才从显示板综合中移除旧 SD 读取链路。
5. 对比显示板净切片占用与时序；目标是显著低于当前 96.59%，而非让两板
   LUT 数字恰好相等。媒体板稳定后再独立推进 4 位 SD 读卡和写卡。

当前 `board_display/` 的资源基线见 [板卡状态](board_status.md)。首批双板
改动不重做整个项目的全量仿真；按控制、收发、帧写入和原子提交四个边界
补定向测试，并以两块真板做最终验收。

## 媒体分片候选格式与当前进度

两板应用层使用 `AA BB CC DD 00 10 LEN_H LEN_L` 头；`LEN` 是后续载荷字节
数。载荷先放 8 字节分片头，再放 `COUNT` 个小端 32 位数据字：

| 载荷字节 | 含义 |
| --- | --- |
| 0–1 | 会话号，小端 |
| 2–3 | 分片序号，小端 |
| 4 | 数据字数 `COUNT`，范围 1–253 |
| 5 | 标志位；bit0 暂定为本段媒体最后一片 |
| 6–7 | CRC16-CCITT-FALSE，小端 |
| 8 起 | `COUNT` 个 32 位数据字，每字低字节先传 |

`LEN = 8 + 4×COUNT`，整个 UDP 载荷字节数为 `16 + 4×COUNT`，最大 1028。
CRC 初值 `FFFF`、多项式 `1021`，覆盖载荷字节 0–5 与 8 起的数据，不含应用头
及 CRC 字段。发送模块先收齐一片并算出 CRC，再发 UDP；接收模块先缓冲整片、
确认长度与 CRC，才逐字交给后级。定向仿真已覆盖 1/7/253 字、独立 CRC
黄金值、坏包和截断包。当前已把固定 7 字分片诊断接入两板 TD 顶层：媒体板
收到 PC 的 `M` 后发送，显示板只统计完整片/坏片并显示在数码管；尚无会话
序号验收、ACK/重发、整图 CRC 或 SDRAM 原子提交。它们是下一阶段的完整性边界。

显示板 `eth_front` 现在只解析 `type=0001` 的命令字节；媒体板的临时命令
转发也用 `type=0001`。这防止媒体 `type=0010` 的像素字节被误认成切图命令。
2026-10-18 上板结果：PC `.1` → 媒体板 `.3` → 显示板 `.2` → PC `.1`
的 `S` 状态往返连续 3 次通过；`M` 触发的固定分片跨板 CRC 接收连续 3 次通过。
这是控制与单片链路的验收，整帧可靠传输仍按上面的事务边界实现。
