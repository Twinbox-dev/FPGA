# 双板媒体系统架构

本文按 2026-10-30 已验收产品更新。图片/控制包字段以 [媒体链路协议](media_link_protocol.md) 为准；多窗口细节见 [实现说明](native_frame_multiview_handoff.md)，视频见 [全屏行队列](video_fullscreen_optimization_20261030.md)，资源见 [板卡状态](board_status.md)。

## 两板职责

| 媒体板 192.168.137.3 / cable1 | 显示板 192.168.137.2 / cable0 |
| --- | --- |
| 原生 SD 只读、FAT32、BMP/WAV、配对列表、按键、轮播、USB UART、HC-08、PC Ethernet、源图/PCM 发送 | 图像校验、补黑/缩小、SDRAM、HDMI、音频、转场、全屏 CV、字幕/OSD/频谱、GT911 和光标 |

媒体板不用 SDRAM 缓存整帧；使用 BRAM 扇区/包缓存和反压。网络传 BMP 实际宽高的 RGB565，保留文件自底向上行序，显示端写入时翻转。每个 32-bit 字打包两个像素，整图奇数像素的末字高 16 位为零。

两边 Ethernet RTL/IP 自包含。媒体端保留 PC 控制入口；显示端普通媒体流使用固定媒体对端 `.3:1`，PC 图片与视频则直接进入 `.2:1`。产品精简网络不能依赖 ping 判断在线，应使用经媒体板的 S/VIEW_STATUS 或正式 READY。

## 路由和控制

| 方向 | 内容 |
| --- | --- |
| PC .1 → 媒体板 .3:1 | V1 `[CMD, ~CMD]`、字幕 |
| PC .1 临时 UDP 端口 → 显示板 .2:1 | Ethernet 页直接上传静态图片及可选 WAV；复用正式媒体帧事务 |
| PC .1 → 显示板 .2:1；显示板 → PC .1:4 | VD/AD 视频行和 PCM 块；VA READY/CREDIT/NACK/健康反馈 |
| 媒体板 .3 → 显示板 .2:1 | 图像/PCM、绝对设置、字幕、窗口 PREPARE/状态请求 |
| 显示板 .2 → 媒体板 .3:1 | READY、图像/音频 RESULT、设置 ACK、窗口状态、GT911 N/P |
| 显示板 .2 → PC 上传 socket | 返回 PC 上传事务的 READY、PREPARE、图像/音频 RESULT 和 VIEW_STATUS |
| 媒体板 .3 → PC .1:2 | V1 ACK/A5、VIEW_STATUS、按需 D 源图快照 |

媒体格式的 TYPE/LEN 为小端；V1 控制格式为大端。目的地址、长度和 owner 在整包发送期间保持，仲裁只在包边界切换。不能把一次 N/P 同时送入原始命令口和控制核脉冲口。

显示设置经显示板实际执行并 ACK 后，媒体端才更新确认值。图像命令的初始 ACK 仅表示接收，最终完成由 RESULT 和 VIEW_STATUS 决定。USB、HC-08、Ethernet、按键、轮播、GT911 共用同一布局/忙规则。

## SDRAM

SDRAM 用户空间为 2,097,152 个 32-bit 字，频率维持 100 MHz：

| 区域 | 起始字地址 | 长度 | 用途 |
| --- | ---: | ---: | --- |
| BUF0 | 0 | 460,800 | 图像 A |
| BUF1 | 460,800 | 460,800 | 图像 B |
| BUF2 | 921,600 | 587,776 | 音频 A |
| BUF3 | 1,509,376 | 587,776 | 音频 B |

两个图像区继续乒乓。多窗口把一块 460,800 字全屏区分成两个 230,400 字槽或四个 115,200 字槽；不为每个窗口保留整张 720p 原图，也不占用音频区。这里的“槽/bank”是逻辑分区，不是 SDRAM 芯片物理 bank。

单图的新图与配对 PCM 完成后才提交；淡入淡出/滑动转场期间保留旧音频，转场结束换源。多窗口首次进入在另一图像区准备整页，齐备后切换；同布局切图写入目标窗的另一页，按帧边界提交窗口页面位，也支持转场。窗口可分散在两页；返回单图时，先隐藏仍占目标整屏写入区的旧窗口并排空读取，才允许写整屏。

进入/退出多窗口保持原音频，多窗口切图不重新传 WAV；返回单图重新装载焦点图和配对 WAV。PC 多窗口图片上传也不允许附加音轨，详见 [转场与音频](multiview_transition_worktree_20261025.md)。

独占视频借用非活动音频区作为 512 行、每行 512 字的环形队列，BRAM 保存完整接收页和小型显示行缓存；不是整帧 SDRAM 提交。通过租约排空旧请求、暂停旧音频后才切入视频，结束后释放并恢复原图片布局和音频。当前不支持视频与三张图片同屏。

## HDMI 路径与 PC D

SDRAM → RGB565 展开/单图转场 → 全屏 CV → 亮度/对比度 → 频谱 → 字幕/OSD → 光标 → AXIS/HDMI。

六种 CV 运行时选择作用于图片合成后的整屏，叠加 UI 不经过 CV；单图、多窗口均可选。视频独占期间强制原图并隐藏叠加 UI，保留音量、状态和停止；停止后恢复用户保存的图片、布局、音频及 CV 等设置。

Ethernet D 从媒体板 SD 重读当前焦点/已提交 BMP，返回原始尺寸、未经补黑/缩小/CV 的源图；它不读取显示板 SDRAM，不代表 HDMI 画面。D 快照的结束握手使用零样本音频事务，不能据此证明实际 WAV PCM 或扬声器输出。显示端像素证据需要 HDMI 观察或独立扫描诊断；诊断构建须保存对应源码和 bit。

## 验证与版本边界

- 当前入口：`boardtest` 定向测试、`scripts/media_sd_board_acceptance.py`、`scripts/dual_board_cmd_probe.py` 和 Web 控制台。
- PC 可模拟任一对端，但固定网络 peer 参数需在隔离诊断工程中匹配；测试后恢复正式 .3↔.2 路由。
- 单板历史设计见 [架构](history/single_board_architecture.md)/[设计](history/single_board_design.md)；`single-V1`、`dual-V1` 等稳定标签不随工作区改动。
- 功能通过、资源通过和静态时序收敛分别记录；负 WNS 不因上板正常而消失。
- 提交按该轮用户授权执行，保存 RTL 和已验收的配套正式 bit/报告。
