# 设计文档 — HDMI 多媒体播放系统（安路选题一）

> **历史初版规格。** 本文的 640×480 时钟、独立仓库与流式音频计划已被
> 当前 720p + SDRAM WAV 设计替代。FAT32/BMP 的早期接口约定仍可供追溯，
> 但修改当前板级 RTL 时请先读 [README](../../README.md)、
> [验证入口](../verification.md) 和现行源码。

平台：HX4S20C / EG4S20BG256（19,600 LUT / 19,600 DFF，片内 SDRAM 2M×32bit，
64×9Kb + 16×32Kb ERAM，4×PLL，193 用户 IO，50MHz 晶振，双 HDMI、TF 卡槽、
8 数码管、16 双色 LED、4 按键、4 拨码、USB 转 UART、千兆网口、蜂鸣器）

## 1. 设计原则

1. **全同步 RTL**：所有逻辑 `always @(posedge clk)`，异步复位同步释放——这是
   Verilator 结果与上板行为一致的前提
2. **纯 RTL、无任何处理器**：规则禁止板外处理器；软核虽字面不违规，但安路无
   官方软核 IP 且评委观感存疑，不引入
3. **RTL 与厂商原语解耦**：本仓库 vsrc/ 不出现 PLL/ERAM 等任何原语；IP 核与
   原语例化、TD 工程在另一个目录实现——两边通过纯 RTL 模块衔接，vsrc 验证
   通过后直接同步给 TD 工程
4. **显示路径硬实时、装载路径尽力而为**：一切仲裁围绕这条
5. **先定格式跑通，再逐步放开**：基础阶段限定 640×480@60、24bit BMP、根目录 8.3 名

## 2. 时钟与 CDC

| 域 | 频率 | 承载逻辑 |
|---|---|---|
| fabric | 100MHz | SD/SPI、FAT32、BMP、SDRAM 控制器与仲裁、UI |
| pixel | 25MHz | 视频时序、TMDS 编码、音频包调度 |
| tmds | 125MHz | DDR 串化（250Mbps TMDS） |

- **SPI 不独立成域**：SD SPI 时钟由 100M 域 ce 分频产生（400kHz 起步 → 25MHz），
  消灭一处 CDC
- PLL_A：50M → 25M + 125M（严格 5:1，串化器每 5 拍装载 10bit）
- PLL_B：50M → 100M
- CDC 唯一难点：fabric(100M) ↔ pixel(25M)，走**行缓冲 BRAM + 格雷码握手**；
  pixel ↔ tmds 同 PLL 相位对齐，计数同步装载
- 音频 48kHz：100M 域 ce（÷2083，实际 48.0077kHz），ACR 的 N/CTS 按实测比率
  配置，仿真断言闭环
- ⚠ 最终时钟方案以官方例程（lab_ex_4/5）为准校准——它已证明 250Mbps TMDS
  在本板可行

接口契约（模块间只许通过以下握手，禁止跨模块直接引用内部状态）：

```verilog
// ---- SD 扇区读（fat32_ro 侧的端口；sd_spi 侧已实现为 i_lba/i_req/i_ready
//      方向互换 + o_data/o_dval/o_done/o_err，见 vsrc/sd_spi.v）----
output [31:0] o_lba;  output o_req;  input i_ready;  // i_ready=1 时采样 o_lba
input  [7:0]  i_data; input i_dval;                  // 扇区数据流 512B 按序
input  i_done;        input i_err;                   // 扇区完成 / 重试耗尽

// ---- 显示行取（sdram_ctrl ← vid_timing，经行缓冲 BRAM）----
output [23:0] o_line_addr; output o_line_req; input i_line_ack;  // 行起始握手
input  [31:0] i_px; input i_px_val; input i_line_done;           // 640 拍

// ---- 装载写（bmp_dec → sdram_ctrl，尽力而为）----
output [23:0] o_wr_addr; output [31:0] o_wr_data; output o_wr_en; input i_wr_ready;

// ---- 乒乓切换（fb_swap ← 装载侧 → 显示侧）----
input  i_img_done;          // 当前装载帧完成
output o_front_sel;         // vsync 边沿原子翻转
```

## 4. SDRAM 子系统（关键设计）

- **布局**：双帧乒乓 640×480×4B = 2.35MB；音频环缓 1MB（M2）；剩余 ~4.6MB 备扩展
- **像素格式**：32bit/px（R[23:16] G[15:8] B[7:0]，高 8 位保留给扩展期 α/调试）。
  简化控制器对齐；若转场+缩放并发带宽吃紧，再改 24bpp packed（省 25%）
- **仲裁优先级**：REFRESH > DISP > LOAD（含音频环缓）
  - DISP 突发上限 16 词，防 LOAD/AUDIO 饿死
  - DISP 行预取提前量：行消隐起点发起（deadline = 行周期 31.7µs；
    预取 640 词 × ≤2 周期/词 ≈ 13µs，富余 ~2.4×）
- **刷新**：64ms/8192 行 ≈ 7.81µs 间隔，单次 ~7 周期，占用 <1%
- 时序参数以例程控制器为基线

## 5. FAT32 只读引擎规格（2026-09-20 约定 v2）

使用约定（用户保证）：**单分区**（只解析 0x1BE 第一项）、**图片只放根目录**。
解析器保留双路径与 LFN 防御：

1. **挂载（双路径）**：读 LBA0 → 首字节 0xEB/0xE9 → superfloppy
   （part_lba=0，本扇区即 BPB）；否则按 MBR：校验 [510]=0x55、[511]=0xAA →
   [0x1C2] ∈ {0x0B, 0x0C} → start_lba = LE32@[0x1C6]，读该扇区 = BPB。
   真卡（Windows 格式化）走 MBR 路径；现有 gen_card 镜像是 superfloppy，
   两条路径都要有测试覆盖
2. **BPB**：spc@[13]、reserved@[14]、nfats@[16]、fatsz32@[36]、rootclus@[44]
   （sanity：bps@[11]==512）→ fat_start = part_lba + reserved；
   first_data = part_lba + reserved + nfats×fatsz32
3. **目录扫描**：沿 rootclus 簇链逐扇区；32B 项：[0]==0x00 停、0xE5 跳、
   attr[11]∈{0x0F, 0x08, 0x10} 跳（LFN 项防御性跳过：Windows 对长名/小写
   名文件必生成 LFN 项，但其 8.3 别名扩展名仍为 BMP——故真卡文件名不限
   8.3，扩展名 .bmp 即可）；扩展名 [8..10]=="BMP" 命中 → playlist 追加
   {cluster = ([20..21]<<16) | [26..27], size = LE32@[28]}，容量 32 项
4. **文件读**：FAT 项位于 fat_start + cluster×4（4B LE），值 ≥0x0FFFFFF8 为
   EOC；lba(c) = first_data + (c-2)×spc；v1 无 FAT 扇区缓存（逐簇重读，
   ~6% 扇区读开销），缓存留作板级优化
5. **健壮性**：SD 层重试沿用 sd_spi；文件层遇坏簇/短读 → 弃图报 E4 下一张

落地状态（2026-09-20，W2 ✅）：golden C++（csrc/fat32_golden.*）+ fat32_ro
+ bmp_dec 已替换 bmp_loader 硬编码方案；4 张卡（主 superfloppy / MBR /
碎片化 / 空）回归全过，碎片卡含测试集自检（golden 断言文件 0 非连续）。
MBR 碎片化配方见 gen_card.sh（填满盘 → 删中间洞 → 拷入大文件，强制两段链）。

## 6. BMP 解码规格

1. **校验**：magic='BM'、biPlanes=1、biBitCount=24、biCompression=0、
   宽×高 = 640×480（基础阶段，否则拒）；bfOffBits 按头实读不硬编码 54
2. **行重组**：BMP 自底向上 → 目标行号 = height-1-源行号；
   每行读 width×3B 后丢弃 (4-(width×3))&3 字节填充（640×480 恰为 0，
   但解析器按通用实现——641 宽测试图专测此路径）
3. **像素**：BGR 字节序 → RGB 装配 32bit 写入后备帧缓冲
4. **拒绝路径**：任何校验失败 → 错误码 E4 + 蜂鸣短鸣 → 下一张，绝不挂死

## 7. 音频通路

- **M1 测试音**（基础门槛"基础音频输出"）：正弦 LUT 256×16bit + 相位累加器，
  1kHz@48kHz 立体声；按键 click / 错误 beep 由 UI 事件触发——够基础分
- **M2 WAV 联动**（"音视频联动"卖点，3a 已落地）：
  - 卡上 IMG001.WAV 与 IMG001.BMP 同名配对（8 字节主名），有则播，无则静音
  - RIFF/fmt/data chunk 链解析，限定 48kHz/16bit/单或立体声（避免重采样）
  - **从卡实时流式，不进 SDRAM**：音频 192KB/s vs SPI 3.1MB/s ≈ 6% 带宽；
    图/音各一个 `fat32_ro` 实例，`sd_arbiter` 仲裁（音频优先 + pending 排队 +
    写目标 FIFO 高水位停流）；双 FIFO 乒乓，续播期写目标切回播放 FIFO 边播边补，
    装载期写装载 FIFO；双就绪原子提交（场同步沿同时切图切音），无配对提交双清静音
  - ~~SDRAM 环形缓冲 1MB~~（2026-09-26 弃用该方案，理由见上；SDRAM 保持纯视频）
- **HDMI 封装**（3b 板级）：16bit 样本 → IEC60958 32bit 子帧；ACR 包周期发送，
  N=6144 基准、CTS 按实测音频率换算；数据岛包只排进 HSYNC 有效辅助窗口

## 11. 决策记录

| # | 决策 | 理由 |
|---|---|---|
| D1 | 纯 RTL，无软核 | 规则精神；安路无官方软核；工作量可控（fat32_ro ≈ 2.5k LUT） |
| D2 | 32bit/px 帧缓存 | 控制器简单；带宽够；24bpp packed 留作优化手段 |
| D3 | SPI 用 100M 域 ce 分频 | 消灭一个 CDC；25MHz < 100M/4 ✓ |
| D4 | 定格式先行（640×480/24bit/根目录/8.3） | 先拿基础分；接口不变逐步放开 |
| D5 | 音频 M1 测试音 → M2 WAV 两级 | M1 是基础分门槛；M2 是"音视频联动"卖点 |
| D6 | 显示读走行缓冲 BRAM 跨域 | 25M/100M 唯一 CDC 点，结构最简单可靠 |
