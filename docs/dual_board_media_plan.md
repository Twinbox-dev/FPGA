# 双板媒体系统：已确认架构与实施计划

本文记录本开发分支的有效协议和待完成阶段。既有显示行为沿用 `single-board-gt911-v1`；板级资源和运行边界以当前 TD 工程及报告为准。

## 1. 两板职责

| 媒体板 .3 | 显示板 .2 |
| --- | --- |
| SD/SPI、FAT32、BMP/WAV 解析、播放列表/配对、自动轮播、实体按键、PC UART/以太网控制入口、媒体包发送 | SDRAM 图像/音频缓冲、HDMI 图像与音频输出、转场、OSD/字幕/频谱、GT911 光标/手势、媒体包校验与提交 |

媒体板不使用 SDRAM 缓存整帧；少量 BRAM 用作扇区、像素、PCM 和 UDP 包缓冲。两边的 Ethernet RTL 和厂商 IP 自包含，不跨工程引用 Verilog。

显示板沿用 V1 四区，地址单位为 32 位字：

| 缓冲 | 起始地址 | 用途 |
| --- | ---: | --- |
| BUF0 | 0 | 图像 A，460800 字 |
| BUF1 | 460800 | 图像 B，460800 字 |
| BUF2 | 921600 | 音频 A，587776 字 |
| BUF3 | 1509376 | 音频 B，587776 字 |

显示板只写非活动缓冲；收到完整图像、配对音频并校验通过前，继续显示旧图/播放旧音频。转场完成后再换音频并向媒体板回报完成。

## 2. 媒体帧生成

沿用 V1 的未压缩 24-bit BMP，最大 1280×720。媒体板读头取宽高，按 V1 居中规则补黑边，生成恰好 1280×720、RGB565、460800 个 32 位字。每字两个像素，先出现的像素在低 16 位；行序保持 BMP 自底向上，不在媒体板翻转。显示板继续用 V1 写入路径的 WRITE_V_FLIP=1。

同 basename 的 WAV 按 FAT 文件列表匹配。合法规格是 24 kHz、8-bit unsigned、单声道 PCM；不扩成网络 24-bit 样本。缺少或不支持 WAV 时传零样本静音事务。

## 3. 正式图像与音频协议

完整字段见 [媒体链路协议](media_link_protocol.md)。正式媒体通路和 D 调试探针分开；正式流使用累计校验，不使用每包 ACK/选择性补包。

一次切图顺序为：

接收端 READY → 图像 BEGIN/DATA/END → 图像结果 → 音频 BEGIN/DATA/END → 音频结果 → 显示板图音提交 → 完成回报

- 图像结果失败时整图重读重发，最多 3 次总发送。
- 音频结果失败时只重读并重发音频，保留已验收图像。
- 图像/音频结束包分别在最后一个数据包后等待 1 ms。
- 接收端只在字数、包序号、校验和样本数完全正确时提交非活动缓冲。

## 4. 网络路由与 PC 控制

网络地址：PC .1、显示板 .2、媒体板 .3；媒体板与显示板使用不同单播 MAC。

| 流量 | 目的地 |
| --- | --- |
| PC V1 命令/字幕上行 | 媒体板 .3:1 |
| 媒体板正式媒体包 0x0020–0x0033 | 显示板 .2:1 |
| 媒体板显示 SET/STATUS_REQ/字幕 0x0040/42/44/45/46 | 显示板 .2:1 |
| 显示板 READY/图像音频结果/SET ACK/状态 | 媒体板 .3:1 |
| 媒体板 V1 ACK/A5 状态、D 原始调试读回 | PC .1:2 |

目的地址和端口按媒体 mux owner 或控制类型逐包选择，在整包发送期间保持稳定。媒体包和显示控制包送往显示板；V1 命令回包与 D 探针送往 PC。

app.py 有 23 个按键字节；媒体侧命令表和显示侧 0x0040–0x0046 字段见协议文档。显示设置使用绝对值，只有显示板 ACK 后媒体板才更新确认状态并向 PC 回 ACK。S 读取显示板真实状态，媒体板再合并媒体状态回 PC。字幕沿用 V1 ASCII/长度/校验语义。L 保留在前端，FPGA 按约定不回有效响应。

媒体控制包发送完成只在 UDP mux 回到 ready 后报告；mux 空闲时等待旧 `stack_ack` 拉低，再授予下一包。这避免紧邻控制包在 UDP 栈仍占用上一包时启动。

## 5. PC 按需取图和仲裁

正常切图只发给显示板。PC 需要当前已提交图像时，媒体板从 SD 重读、补黑边后以正式帧发送给 PC，不触发显示切换。该正式 PC 快照/仲裁仍是待实现的 dual-board 项；当前 D 是媒体侧原始 BMP 调试探针，不代替此功能。

- 显示板 READY、结果、重试和本地控制优先。
- PC 取图最多保留一笔请求；连续请求合并。
- 新的正常切图请求到达时，PC 帧在当前 UDP 包结束后中止，优先给显示板装图；被中止的 PC 帧丢弃。
- 导航请求在媒体装载/显示提交忙时忽略；其他 V1 参数命令可在媒体包之间处理。

## 6. 当前迁移状态

媒体板源已换成正式图像/PCM、V1 控制和字幕实现，并增加 .1/.2 按包路由。TD 综合、布局布线和路由选择仿真通过；媒体板分支 bit 尚未用物理双板验证。当前报告：12231 LUT、8412 FF、21 BRAM9K、2 BRAM32K、2 DSP、6948 slices；setup WNS −2.993 ns、hold WNS −3.188 ns，时序未收敛。

单板媒体实测：6 张图、4 段 WAV、2 段静音；N 循环全六帧、P 单帧、D 640×480 探针、自动轮播、全部以太网 app.py 命令、S 双包和字幕均通过。UART 逻辑有 RTL 仿真覆盖，本次主机没有 FPGA UART 端口。

## 7. 后续实施与验收

1. 媒体板移植：已完成源码迁移和 TD 综合/布局布线，待提交。
2. 显示板接收 RTL：下一阶段。保持 V1 HDMI/SDRAM 图像通路，新增 0x20–0x33 收包/校验、非活动缓冲写入、结果/状态回包和 0x40–0x46 显示控制。
3. 显示板单板验证：用 PC 媒体发送器发已知 RGB565 帧、PCM、控制包；读回 SDRAM 与原始 golden 比对，再检查状态/ACK。无采集设备时，HDMI/模拟音频的人工视听仍需用户最终确认。
4. 双板联调：两板同时上电，验证 .3→.2 READY、图像、音频、原子提交、切图和显示控制；PC 只发命令/收状态与按需探针，不转发正式媒体。
5. 双板全功能稳定后，再从显示板源列表移除旧 SD/FAT/BMP/WAV 路径；SPI→SD 读写升级另开阶段。

反馈丢失、接收端重启后的重新同步和 PC 快照中止策略在实际双板链路接入时按最简状态表定稿；未验证前不写成已完成。
